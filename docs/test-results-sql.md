# نتائج اختبار مخطط Supabase (PostgreSQL 16 حقيقي)

ملاحظة: يختبر SQL والأمان والتزامن فعلياً، ويحاكي auth.uid() ودور authenticated كما تفعل Supabase. لا يختبر طبقتي GoTrue/PostgREST الفعليتين.

| الاختبار | النتيجة | ملاحظات |
|---|---|---|
| المخطط يُطبَّق بلا أخطاء ويمكن تشغيله مرتين (آمن للتحديث) | ✅ | مرتان بلا خطأ |
| الأمان: بلا تسجيل دخول مرفوض، ودور anon لا يستطيع استدعاء الدوال، والجداول مقفلة مباشرة | ✅ | unauth/anon/جداول/دوال داخلية كلها مرفوضة |
| إنشاء متجر: المالك owner مع رمز انضمام؛ ولا يُنشأ متجر ثانٍ لنفس المستخدم | ✅ | رمز الانضمام 20 خانة |
| الانضمام برمز: الخاطئ يُرفض، والصحيح (بأي حالة أحرف وفواصل) ينضم كموظف ولا يرى الرمز | ✅ | ok |
| عزل المتاجر: متجر آخر لا يرى بيانات الأول ولا يستطيع تعديلها | ✅ | ok |

| الحذف: مستند محذوف يختفي من التحميل الأول ويصل كـ tombstone للأجهزة التي تتابع، ويمكن إعادة إنشائه | ✅ | ok |
| الموظف: يبيع ويكتب المنتجات والفواتير، لكن لا يكتب المستخدمين ولا يمسح مخزناً ولا يستعيد نسخة | ✅ | ok |
| مخازن غير معروفة ومستندات مشوّهة تُرفض | ✅ | ok |

| المالك: مسح مخزن كامل، تدوير رمز الانضمام (القديم يتوقف)، وطرد موظف | ✅ | ok |

| التزامن: 12 جلسة تكتب مستندات مختلفة معاً — كلها تنجح وأرقام seq فريدة ومرتّبة | ✅ | ok |
| المتجر: النشر للمالك فقط، الـ slug يُتحقَّق منه وفريد، وقبل النشر الزائر لا يرى شيئاً | ✅ | owner فقط، slug صحيح وفريد |
| المتجر: الكتالوج العام لا يكشف التكلفة/المورد/الكمية الدقيقة، ويخفي المخفي والمؤرشف، ويحسب العروض | ✅ | قائمة بيضاء + عروض + توفر + صور عند الطلب |

| الأمان: anon لا يصل لدوال الموظفين ولا للجداول، والمستخدم غير العضو مرفوض | ✅ | جداول ودوال داخلية ودوال موظفين كلها مغلقة أمام anon |
