# نشر كاشير الدكان على GitHub (رابط https مجاني)

**GitHub** يحفظ **ملفات التطبيق** (الكود) و**GitHub Pages** يشغّلها كموقع على رابط `https`، فتفتحه من أي جهاز وتثبّته على الهاتف وتعمل الكاميرا — بدون تشغيل أي خادم عندك.
**بيانات المتجر لا تُرفع إلى GitHub أبداً**: تبقى في متصفح الجهاز (الوضع المحلي) أو في Supabase (الوضع السحابي).

> ⚠️ المستودع **العام (Public)** يراه الجميع: كوده فقط، لا بيانات فيه. GitHub Pages للمستودعات الخاصة يحتاج خطة مدفوعة (بحسب علمي، تحقق من صفحة الأسعار). لا تضع في المستودع أي مفتاح سرّي أو ملف `data/key.txt` (الملف `.gitignore` يمنعه).

## 1) أنشئ المستودع
1. ادخل إلى **github.com** وأنشئ حساباً إن لم يكن عندك.
2. زر **+** ← **New repository**. الاسم مثلاً `kashier`. اختر **Public**. **لا** تضف README أو .gitignore. ثم **Create repository**.

## 2) ارفع الملفات
### الطريقة أ — GitHub Desktop أو سطر الأوامر (الأضمن، لأنها ترفع الملفات المخفية)
فك ضغط المشروع ثم داخل المجلد:
```bash
git init -b main
git add .
git commit -m "كاشير الدكان 2.0"
git remote add origin https://github.com/اسمك/kashier.git
git push -u origin main
```
(أو برنامج **GitHub Desktop**: File ← Add local repository ← Publish repository.)

### الطريقة ب — من موقع GitHub مباشرة (بدون برامج)
1. في صفحة المستودع: **uploading an existing file**.
2. افتح مجلد المشروع بعد فك الضغط، **حدّد كل ما بداخله** (وليس الملف المضغوط نفسه؛ GitHub لا يفك الضغط) واسحبه إلى الصفحة. ثم **Commit changes**.
3. **مهم:** الملفات التي تبدأ بنقطة (`.github` و`.gitignore` و`.nojekyll`) قد لا تُرفع بالسحب. أنشئ ملف النشر يدوياً: **Add file ← Create new file**، واكتب في خانة الاسم بالضبط `.github/workflows/pages.yml` (الشرطة المائلة تُنشئ المجلدات)، والصق محتوى الملف الموجود في المشروع بنفس المسار، ثم **Commit**.

## 3) فعّل النشر
1. **Settings ← Pages**.
2. تحت **Build and deployment ← Source** اختر **GitHub Actions**.
3. اذهب إلى تبويب **Actions**: ستجد تشغيلاً باسم «Deploy to GitHub Pages». انتظر حتى يصبح أخضر (دقيقة تقريباً). إن لم يبدأ: **Run workflow**.
4. رابط تطبيقك: `https://اسمك.github.io/kashier/` (يظهر أيضاً في Settings ← Pages).

> كل مرة ترفع تعديلاً إلى فرع `main` يُنشَر تلقائياً بإصدار جديد (`2.3.0+رقم`) فيتحدّث التطبيق عند المستخدمين دون فقدان بياناتهم. **بعد كل تحديث افتح التطبيق مرتين** (الأولى تنزّل الجديد في الخلفية، والثانية تعرضه).

## 4) اربطه بـ Supabase (اختياري)
إما من الإعدادات داخل التطبيق على كل جهاز، أو **مرة واحدة** هنا: من صفحة المستودع افتح `src/config.js` ← أيقونة القلم ✏️ ← ضع الرابط والمفتاح العام:
```js
supabase: { url: 'https://xxxxxxxx.supabase.co', anonKey: 'المفتاح العام' },
```
← **Commit changes**. بعد دقيقة يتصل التطبيق على كل الأجهزة بمشروعك. التفاصيل في [`SUPABASE.md`](SUPABASE.md).
**لا تضع `service_role` ولا `secret` أبداً.**

## 5) ثبّته على الهاتف
افتح الرابط على الهاتف: أندرويد/كروم ← ⋮ ← «تثبيت التطبيق». آيفون/سفاري ← مشاركة ← «إضافة إلى الشاشة الرئيسية». الكاميرا تعمل لأن الرابط `https`.

## تحديث مستودع موجود إلى إصدار جديد (مهم)
بعض الملفات تغيّر مكانها بين الإصدارات (مثلاً `charts.js` و`shell.js` و`routes.js` صارت داخل `src/ui/`). لذلك **لا ترفع الإصدار الجديد فوق القديم فقط**، لأن الملفات القديمة تبقى هناك بلا فائدة وتُحمَّل مع الموقع:
1. احذف من المستودع المجلدات القديمة: `src` و`css` و`icons` و`supabase` و`docs` و`scripts` و`tests` و`server` و`.github` (من صفحة المجلد: ⋯ ← Delete directory) وكذلك الملفات في الجذر: `index.html` و`store.html` و`sw.js` و`manifest.json` و`package.json` و`README.md`. **احتفظ بنسخة من `src/config.js` إن كنت عدّلته.**
2. ارفع **محتويات** المجلد `kashier-pro` من الأرشيف الجديد (لا الأرشيف نفسه ولا المجلد الخارجي)، ومنها المجلد المخفي `.github` وملف `.nojekyll`.
3. أعد وضع رابط Supabase والمفتاح العام في `src/config.js` إن أردتهما ثابتين لكل الأجهزة.
4. تحقق من تبويب **Actions**: يجب أن ينتهي النشر بعلامة خضراء. ثم افتح الموقع وحدّث الصفحة مرتين (النسخة الجديدة تصل في المرة الثانية).
5. اختبر `…/store.html` على الموقع. إن ظهر «404» فالملف `store.html` لم يُرفع أو لم يُرفع `.github/workflows/pages.yml` المحدّث.

> المستودع الذي يحوي `X` أو ملفات `.js` مبعثرة في جذر `src` فيه بقايا رفع قديم؛ يُحذف كله بالخطوة 1.

## التحديث من الجوال بلا حاسوب (ملف `apply-zip.yml`)
المتصفح على الجوال لا يرفع مجلدات، فجهّزتُ ملف تشغيل يفكّ الأرشيف داخل GitHub ويستبدل الملفات:
1. أنشئ في المستودع الملف `.github/workflows/apply-zip.yml` (Add file ← Create new file) والصق فيه محتوى `docs/apply-zip.yml`، ثم Commit. (مرة واحدة فقط.)
2. لكل تحديث: Add file ← Upload files ← اختر الأرشيف الجديد (`kashier-pro-v….zip`) ← Commit.
3. تبويب **Actions** ← **Apply uploaded zip** ← **Run workflow**، واكتب **اسم الأرشيف الجديد** في الخانة ← Run.
4. يحذف كل الملفات القديمة (عدا `.github`)، ويضع الجديدة، ويحتفظ بملف `src/config.js` إن كان فيه رابط Supabase، ويحذف الأرشيف. ثم يبدأ نشر Pages (إن كان موقعك ينشر من الفرع فيبدأ تلقائياً، وإلا حدّث صفحة README بتعديل بسيط ليبدأ).
> لا يستطيع هذا الملف تعديل مجلد `.github` نفسه (قيد من GitHub)، فإن تغيّر `pages.yml` في إصدار جديد فعدّله يدوياً.

## إن لم تُرد GitHub Actions
Settings ← Pages ← Source: **Deploy from a branch** ← `main` / `(root)`. ويجب حينها تشغيل `node scripts/build.mjs 2.3.1` (برقم أعلى) على جهازك قبل كل رفع ليتحدّث التطبيق عند المستخدمين.

## مشاكل شائعة
| المشكلة | الحل |
|---|---|
| صفحة 404 على الرابط | انتظر دقيقة بعد أول نشر، وتأكد أن Source = GitHub Actions وأن تشغيل Actions أخضر. |
| تشغيل Actions أحمر | افتحه واقرأ الخطوة الحمراء. غالباً ملف `pages.yml` ناقص أو Pages لم تُفعَّل (الخطوة 3). |
| الكاميرا لا تعمل | افتح الرابط `https://…github.io/…` وليس ملفاً محلياً أو `http`. وامنح المتصفح إذن الكاميرا. |
| لا أرى التحديث | افتح التطبيق مرتين، أو الإعدادات ← النظام ← «التحقق من وجود تحديث». |
